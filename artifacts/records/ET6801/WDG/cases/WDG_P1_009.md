# WDG_P1_009 — WDG窗口超时系统复位测试

整理时间：2026-09-15；新增 Case 的首次执行结论。

适用基线：ET6801 / FPGA（单核 Profile `et6801_fpga`）；源码版本 `546c3a2` 之后的修正提交，固件 `et6801-silicon-common-v0.1`；bitstream/设备身份未知。不把本轮 FPGA 结果写成 Silicon 结论。

## 结论：IRQ源必须关闭，否则本Case自己破坏复位

RTL（`WDG_CONTROL`）给出决定性条件：`assign rst_req = (wwdg_cur_val == 32'h0)`，且
`assign int_reload_req = ... | (int_raw_rpt & ~wwdg_rst & cfg_int_clr) | ...`。

因此清中断（`cfg_int_clr`）会触发计数器重载。一旦使能 timeout IRQ 源，Service 回调
`et_wdg_wrap_irq_clear` 每次都会把计数器推回 Low 以上，`cur_val` 永远到不了 0，
`rst_req` 不会拉高，窗口模式下系统不复位。手动诊断在 ET6801 FPGA 上复现了两种行为：
清中断则中断风暴且不复位，不清中断则安静递减到 0 并复位。

修正：本 Case 保持 IRQ 源关闭（`irq_disable`），让计数器越过 Low 后继续递减到 0；
Reload 取 `0x100000`，Low/High 取 Reload 的 50%/60%，使完整路径在可观测时间内走完。

本轮 FPGA 实测 PASS：控制链中断、新 Session 建立、目标 RECORD.RESET 置位、
对照保持 0、清除后复读为 0。

## 与WDG_P1_003的分工

`WDG_P1_003` 使能 IRQ 源，承载"真实 IRQ 投递 + 中断记录"；系统复位判据由同轮模式承担。
本 Case 承载"窗口模式下计数器走到 0 形成复位"。两者对 IRQ 源的取舍相反，不可互相套用。

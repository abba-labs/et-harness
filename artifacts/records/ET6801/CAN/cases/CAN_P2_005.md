## 问题：外部回环时 Peer 只听捕获超时

本轮单节点 FAIL。决定性观测（错误文本不是根因）：

- Normal：`CONFIG.LOOPBACK=0`，Peer 捕获 Classic ID=0x123 帧，本地 TX completed 置位。
- Internal：`CONFIG.LOOPBACK=1`，本地 RX 两帧（序号 1/2）；Peer `silent_capture=None` 且 `peer_error=0`（100 ms 静默窗口）。
- External：`CONFIG.LOOPBACK=2`，本地 RX 首帧（序号 3，ID=0x123）成功；Peer 只听捕获 `TimeoutError: ... CAN1: receive timeout; error=0x00000004`。外部第二帧 Oracle 未完成。

## 未关闭问题与适用条件

根因未定位。外部回环忽略 ACK 并使用内部反馈，本地 RX 成功不能证明物理 TX/收发器/总线输出正确；不能直接归因“无 ACK”。0x4 对应既有 ZLG `CAN_PASSIVE` 标志，单个标志不证明持续 error-passive。Normal 正对照降低静态接线或固定速率错误嫌疑，但不替代模式切换后的物理 TX 证据。用户曾明确暂停该项排查；本轮只是同一 FAIL 的复测记录，不是恢复排查。

适用条件：ET6801 / FPGA / `7106a1562269da95d060e2cd756d53eef7e156d4` / source_dirty=true / `et6801-silicon-common-v0.1` / 无参数。bitstream/设备身份未知。

已试过 / 还缺：本轮再次失败于外部捕获。恢复条件仍是用户明确要求后制定独立物理 TX 观察与 Peer 只听方案。增加 Timeout、移除外部捕获或改用普通 ACK 不能作为通过本 Case 的修复。

## 2026-09-12 单变量对照实验结果（诊断，不计入 PASS/FAIL）

用同一 DUT、同一接线、同一 1 Mbit/s 配置，只改变盒子的 `listen_only`，实测：

| DUT 模式 | 盒子模式 | DUT TX | 盒子捕获 |
|---|---|---|---|
| External | 正常（`mode=0`） | completed=1 | **捕获到** ID=0x123 |
| External | 只听（`mode=1`） | completed=1 | **超时** |
| Normal | 正常 | completed=1 | 捕获到 |
| Normal | 只听 | completed=1（关自动重发后） | 超时 |

结论与边界：

- **DUT 的 TX 引脚输出正常**：同一次 External 下，正常模式盒子收到帧，说明物理引脚确有输出；原“引脚可能未输出”的怀疑不成立。
- **失败跟随盒子模式，不跟随 DUT 模式**：盒子 `mode=1` 时两个 DUT 模式都收不到，`mode=0` 时都能收到。
- **“无 ACK 导致 DUT 发送不完成”不成立**：关闭自动重发后，无 ACK 下 `TX.COMPLETED=1`、`pending=0`、协议状态无错误（`last_error=NONE`、`error_passive=False`、TEC/REC=0）。此前 Normal+只听观察到的 `wait_tx_complete` 超时来自自动重发持续重试，不是 ACK 缺失本身。
- **驱动与 ABI 已核对无误**：厂商 `zlgcan.h` 定义 `mode` 为 `BYTE`，语义“0 正常、1 只听”；本仓库 `_zlg_abi.FdConfig` 与厂商 `ZFDConfig`/`canfd` 结构逐字段一致，`zlg.py` 写 `mode = int(listen_only)` 语义正确。
- **仍不能判定为盒子故障**：本台架只有 CAN1 可用（CAN0 打不开），无第二个独立发送方，因此“listen-only 能否收到任意帧”的对照无法执行；`ZCAN_ReadChannelStatus` 在本设备返回 0，读回不可用。
- 该 Case 的 `bench` 要求“能忽略无 ACK 并发送完整合法 EOF、捕获 ACK 槽”的受控 Peer；本台架的 ZLG USBCANFD-200U 在 `mode=1` 下未观测到该捕获能力，属**观测手段缺口**，不是 DUT 结论。
- 知识文件确实记录过“只听捕获未验证”：仓库单测只覆盖 Fake（`test_can_box.py:174`），README 亦声明“ABI/模型回归通过不代表实际盒子型号每个参数已通过硬件验证”。

# CAN_P2_005 — 内外回环物理隔离，外部捕获暂停排查

整理时间：2026-09-08 16:02 CST；不是新增测试或问题关闭。

适用基线：ET6801 / FPGA；历史测试完成于2026-09-08 01:12 CST，源码`e0f70ef9f353f4d8a239bbd3778c735c01897d0b`（clean）。板卡身份与bitstream版本未记录，不外推到其他FPGA版本或Silicon。

## 已确认现象

历史单节点FAIL。相同接线下Normal模式、正常ACK的捕获正对照成功；内部回环两帧本地收发与100 ms静默窗口通过。切到外部回环后首帧本地RX通过，但Peer listen-only捕获超时，错误标志0x4；外部两帧的完整Oracle尚未完成。

本Case需要同时证明本地回环与独立外部观察有效。只读模式位、本地RX或无效捕获窗口均不能替代物理外发判断。

## 判断与暂停边界

根因未定位，尚无已验证修复。外部回环忽略ACK错误并使用内部反馈，本地RX成功不能证明物理TX、收发器或总线输出正确；不能直接归因“无ACK”。0x4对应既有ZLG头文件的CAN_PASSIVE标志，单个标志不证明当前持续处于error-passive状态。

Normal正对照降低静态接线或固定速率错误的嫌疑，但不替代模式切换后的物理TX和只听捕获证据。P1_011在正常ACK Peer条件下通过，也不能关闭本问题。

用户已明确暂停该项排查。迁移不恢复测试，不修改Case、Timeout、ACK策略或盒子配置，不把FAIL改成SKIP/PASS。

## 恢复条件

仅在用户明确要求继续后，先制定独立物理TX观察与Peer只听接收方案，再经过硬件人工门禁。应保留正常ACK正对照与内部静默对照，完整核对外部两帧。增加Timeout、移除外部捕获或改用普通ACK不能作为通过本Case的修复。

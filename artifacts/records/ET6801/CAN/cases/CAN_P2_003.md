# CAN_P2_003 — ECC Force中断链语义待确认

适用基线：ET6801 / FPGA；历史测试完成于2026-09-08 01:12 CST，源码`e0f70ef9f353f4d8a239bbd3778c735c01897d0b`（clean）。板卡身份与bitstream版本未记录，不外推到其他FPGA版本或Silicon。

## 已确认现象

Corrected/Uncorrected两个参数均FAIL，停在首个目标can0的masked阶段。FORCE=3、MASK=3时，EN=1读得RAW=1，EN=2读得RAW=2；STATUS均为0，而当前Case期望RAW=3。100 ms窗口无ISR投递，不能据此声称全部中断链通过。

后续unmask、ISR实例/源路由、独立Clear、再次Force和can1/can2轮转没有完成。原始失败不是“只差修改Expected”的已定位缺陷。

## 判断与尚缺依据

现象与EN参与强制Raw产生相符，但两个样本不足以建立硬件真值表。既有软件检查表明Driver直接读取RSTATUS并提取源位，未在PC显示层按EN过滤；仍缺ET6801 ECC中断封装RTL或明确逻辑说明。Bosch内核的ECC错误指示不能直接推导ET外围EN/FORCE/RAW关系。

尚无已验证修复。若硬件规格不支持保留未Enable另一源的Raw，应评审Case刺激构造并保留独立Mask、ISR和Clear覆盖，不能直接把Expected从3改成当前实测值。

## 下一步闭环条件

先确认封装逻辑；必要时另经人工门禁执行MASK=3、逐点先Clear的EN=0/1/2/3与FORCE=1/2/3矩阵，保留Raw、Status及ISR计数。依据规格裁决Case或FPGA实现，再完整复测两源与全部实例。

本Case只Force中断，不向Message RAM注入真实错误；即使以后通过，也不能证明ECC检测、纠错或不可纠错数据行为。

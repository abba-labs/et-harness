# CAN_P1_020 — ISO / Non-ISO格式正反例

整理时间：2026-09-08 16:02 CST；不是新增测试或问题关闭。

适用基线：ET6801 / FPGA；历史测试完成于2026-09-08 01:12 CST，源码`e0f70ef9f353f4d8a239bbd3778c735c01897d0b`（clean）。板卡身份与bitstream版本未记录，不外推到其他FPGA版本或Silicon。

## 已确认现象

8个参数节点中2 PASS、6 FAIL。两种长度16/64-byte均有相同分组现象：ISO/ISO通过；4个请求DUT Non-ISO的节点在配置读回仍为false处失败；另2个DUT ISO、Peer Non-ISO节点没有建立有效发送刺激，Peer accepted=0。后二者不能和DUT配置读回失败合并成同一根因。

方法的关键是先核对DUT/Peer实际格式：同格式要求双向完整帧；失配要求已发生的Peer刺激、首次协议错误和100 ms内无有效RX；最后重新匹配恢复。仅超时或未入队不能证明格式互斥。

## 判断与尚缺依据

尚不能确认Driver缺陷，也不能确认该FPGA实现不支持Non-ISO。DUT配置位不可改变可能与综合参数有关，但缺少当前bitstream对应的`iso_only_g`等综合配置，不能把推测写成芯片结论。Peer不接受发送需要独立检查其设备格式能力、配置与发送结果，不能用DUT读回解释。

尚无已验证修复。不得删除失败节点、只保留ISO/ISO或把请求回显当实际配置来获得PASS。

## 下一步闭环条件

先取得FPGA综合配置和明确bitstream身份。若能力允许切换，再经独立硬件人工门禁逐步读INIT、CCE、NISO，区分配置窗口写入失败与后续覆盖；Peer问题单独验证。最终需复测四组格式乘两种长度的全部8节点以及恢复段，不以单个配置位变为1宣称完成。

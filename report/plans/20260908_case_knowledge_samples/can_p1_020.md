# CAN_P1_020 — CAN FD ISO与Non-ISO格式

知识样稿，待确认；整理时间：2026-09-08 14:27 CST。不是新增测试记录。

适用基线：ET6801 / FPGA；历史测试完成于2026-09-08 01:12 CST，源码`e0f70ef9`（clean）。板卡身份及bitstream版本未记录；当前两类问题均未关闭，根因未确认。

## 现象分组

条件：仲裁500 kbit/s、数据2 Mbit/s、BRS开启；每组分别测16/64-byte。

| DUT / Peer格式 | 结果 | 失败位置或观测 |
|---|---|---|
| ISO / ISO | 2 PASS | 本组通过 |
| Non-ISO / ISO及Non-ISO / Non-ISO | 4 FAIL | DUT请求Non-ISO，`CONFIG.NON_ISO`实读为false |
| ISO / Non-ISO | 2 FAIL | Peer发送接受数为0 |

六个失败不能直接归为同一根因；格式读回失败的节点也不能当成总线Non-ISO收发已执行。

## 问题一：DUT Non-ISO配置未保持

已知：Bosch定义`CCCR.NISO[15]`；综合参数`iso_only_g=1`时该位保留且读0。IP文档支持Non-ISO，不代表当前FPGA实例启用了它。

已查：ET6801位号与掩码一致，Case等待INIT后配置，Service/Wrap传参未发现明显转换错误。当前读回发生在RAM、Filter、Loopback、Bus配置之后，不能区分“写入未生效”与“后续被覆盖”。同轮WMM16通过，削弱了通用配置写保护路径全部失效的解释，但不能证明NISO写入正确。

尚无已验证修复。优先取得当前bitstream对应的`iso_only_g`配置；若禁用而目标规格要求支持，交由FPGA侧处理。若已开放，经独立硬件人工门禁批准后，分别读取写入前、写入后及各后续配置步骤的INIT/CCE/NISO，定位失效位置。不能将CCE切换本身认定为NISO清零原因。

## 问题二：Peer Non-ISO发送未被接受

已知：DUT ISO、Peer Non-ISO的两个节点均返回Peer接受数0；既有调查确认ZLG枚举与适配器设置一致，但API配置成功不证明Peer真实发出了Non-ISO帧。

尚无已验证修复。独立检查Peer的实际Non-ISO发送能力与发送失败信息；不能仅因DUT侧存在问题，就把这两个节点归因于DUT的NISO。

## 关闭条件与复用提醒

修复后按本Case全部8个节点验证同格式双向收发、失配错误及ISO恢复；单独读回NISO成功不足以关闭问题。记录修复版本及对应bitstream身份，未覆盖的节点继续保留未闭环状态。

排查类似功能位时，先分清“IP支持”“综合实例开放”“配置写入/保持”“实际总线行为”，避免把某一层通过当成整条功能链通过。

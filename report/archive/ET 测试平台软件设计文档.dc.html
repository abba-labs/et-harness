A0

分层契约与不变量(框架层骨架)

本文只定义与 IP 无关的框架层——协议封套、分发底座、注册/自启动、能力模型、可靠性、执行模型。单个 IP 的命令天然各异,那是"填空"(压缩到末章附录)。框架层的价值全在三条硬约束、一个依赖方向、一份不变量清单、六个精确接缝里,下面逐一钉死。

A0.1　三条硬约束(整份架构的地基)

① 薄固件 / 聪明主机
固件只做确定性执行,回原始量、不判 PASS/FAIL;一切校验、裁决、重试、判据都在主机。固件无业务智能 → 可移植、可预测。
② 复用 SDK,不自造
只复用三芯片 SDK 里与 RTOS 无关的件：ringbuff / tr_crc / 外设驱动。不用 et_shell/RTOS;命令自注册自己用一个 .ops 链接段搬定。
③ 全静态 / 单在途
固件无 malloc、定长缓冲;链路严格一发一收,任一时刻仅一帧在途 → 幂等单槽即够、内存峰值可静态推算。

P1

命令与通信协议(裸机超循环,机器/人类双模)

命令天然是 「<dev> <cmd> [k=v]…」 文本行:主超循环自己收字节组行、按空格分词、查 registry 链接段分发。机器模式在此之上加封套(seq/CRC/幂等)让主机可靠驱动;人类模式去封套、加回显,便于串口助手直接敲。两模共用同一命令表与分发。串口 115200-8N1。

唯一真相源:命令名、参数键、观测键由各 IP 的契约(主机 contracts/<ip>.yaml)与固件 handler(REGISTER_HANDLER)共同声明。加任何 IP,本章的协议封套、双模、CRC/幂等规则一行不改。

1.3　机器模式帧语法(请求 / 应答同构 · BNF)

proto/wire.bnf · 封套包住命令行
frame    = "#" seq SP body SP "*" crc LF
seq      = 4*HEXDIG                 ; 0000..FFFF 循环,幂等用
body     = req-body / resp-body
req-body = dev SP cmd *(SP kv)      # 即人类模式命令行:can loopback …
resp-body= status *(SP kv)          # status 行
status   = "OK" / "ERR" / "NA" / "LOG"
dev      = "sys" / "can" / "adc" / …   cmd = 1*(ALPHA/DIGIT/"_")
kv       = key "=" val
val      = int / hex / enum / b64   ; 见 1.4
crc      = 2HEXDIG                  ; tr_crc,覆盖 "#"..末尾 " *" 前
SP = %x20   LF = %x0A

# 请求    #0042 can loopback inst=0 data=0x1122334455667788 dlc=8 *3C
# 应答    #0042 OK rx=0x1122334455667788 dlc=8 err=0 *A7
# 多行    #0043 LOG stage=arm *11        (0..N 行中间诊断)
          #0043 OK samples=64 *5E       (最后一行是终态 OK/ERR/NA)

1.4　载荷类型编码(文本行为主)

int十进制  inst=0  dlc=8
hex0x 前缀  data=0x55AA
enum符号名  mode=loopback
b64b64: 前缀  buf=b64:SGVsbG8=
99% 观测量是小标量 → 纯文本一行(可读、串口助手直看)。仅大数组 / 内存 dump(如 ADC DMA 抓数千点)用 b64: 编码,超单帧上限则切块多帧传,主机按 seq 拼回。

1.6　seq / 超时 / 重试 / 幂等语义(可靠性契约)

seq 幂等(单槽即够)
主机每请求 seq+1。链路严格一发一收,任一时刻仅一帧在途,新请求 seq 恒为上次 +1、绝不撞车。固件只缓存上次 seq + 上次应答;相同 seq 直接重放,不重复副作用。
超时 + 重试(主机侧)
发帧后 RESP_TIMEOUT 内未收完整合法终态帧 → 重发同 seq,至多 MAX_RETRY;仍失败 → 判 agent 无响应,上抛。
CRC / seq 校验(固件侧)
CRC 不符 → 丢整帧、不回应(靠主机超时重发);seq 撞缓存 → 重放;新 seq → 正常执行。
会话与体检
主机连上先 sys mode machine → sys ping → 固件回 caps_hash;主机比对能力表,不符 fail-fast。

import serial   # pyserial
from .proto import codec

class SerialLink:
    def __init__(self, port, baud=115200,
                 timeout=0.5, max_retry=3):
        self._ser = serial.Serial(port, baud, timeout=timeout)
        self._max_retry = max_retry

    def xfer(self, frame: bytes) -> bytes:   # 发一帧,收一帧;幂等重试

class HardwareTarget(Target):
    def __init__(self, link, resolver):
        self._link = link; self._resolver = resolver
    def run(self, op, **kw) -> Result:
        self._resolver.check(op, kw)      # L3 裁决
        req = codec.encode(op, kw)        # L4 编码→"#seq can loopback …"
        line = self._link.xfer(req)       # L5 发送
        return codec.decode(line)         # → Result
    def reset(self, scope="chip"):
        self._link.xfer(codec.encode("sys.reset",{"scope":scope}))

  char line[FRAME_MAX_LEN]; int n=0, c;
  board_init();                  // 时钟 + UART + RX中断 + WDG

    wrap(&last,seq,rc2status(r.rc),&r); send_frame(&last);
    last_seq=seq; n=0;
  }
}

// CRC-8/SMBUS  poly=0x07 init=0x00(与主机逐位一致)
uint8_t crc8(const uint8_t *p, int n){
  uint8_t c = 0;
  while(n--){
    c ^= *p++;
    for(int i=0;i<8;i++)
      c = (c & 0x80) ? (c<<1)^0x07 : (c<<1);
  }
  return c;
}
// n 位十六进制字符 → 数值
static uint32_t hexn(const char *p, int n){
  uint32_t v = 0;
  while(n--){ char x=*p++;
    v = (v<<4) | (x<='9' ? x-'0' : (x|0x20)-'a'+10); }
  return v;
}

A3.2　帧封套 · proto/frame.c(unwrap / wrap)

unwrap() · 剥封套 + 校 CRC + 取 seq
// "#0042 can loopback inst=0 *3C"(无 LF) → seq + body
// CRC 覆盖 '#'..' *' 前；坏帧返回 false(丢弃不回应)
bool unwrap(const char *line, int n, uint16_t *seq, char *body){
  if(n < 8 || line[0] != '#') return false;
  int star = -1;                    // 从尾部找 " *"
  for(int i=n-3; i>0; i--)
    if(line[i]==' ' && line[i+1]=='*'){ star=i; break; }
  if(star < 0) return false;
  if(hexn(line+star+2,2) != crc8((const uint8_t*)line, star))
    return false;                   // CRC 不符
  *seq = (uint16_t)hexn(line+1, 4); // #SEQ
  int blen = star - 6;              // body 在 "#SEQ " 之后
  if(blen < 0 || blen >= FRAME_MAX_LEN) return false;
  memcpy(body, line+6, blen); body[blen] = 0;
  return true;
}
wrap() · 组应答帧 + 附 CRC
// resp → "#0042 OK rx=0x.. err=0 *A7\n"，返回长度
int wrap(char *out, uint16_t seq,
         const char *status, const resp_t *r){
  int p = sprintf(out, "#%04X %s", seq, status);
  for(int i=0;i<r->kv_n;i++)
    p += sprintf(out+p, " %s=%s", r->kv[i].k, r->kv[i].v);
  uint8_t c = crc8((const uint8_t*)out, p);  // 同 unwrap 覆盖
  p += sprintf(out+p, " *%02X\n", c);
  return p;
}

A2

机器封套 seam(框架的心脏)

超循环本身很简单;真正要钉死的是机器封套这一薄层 —— 它把"给人看的一行命令"升级成"能被主机可靠驱动的一帧"。封套只接管两个点:读一整行(组帧 + 剥封套 + 校 CRC + 查 seq)和写一整行(加 seq/CRC + 存幂等单槽)。其余(收字节、分词、查表、handler)机器/人类两模完全共用。

A2.1　核心决定:封套只包读写两点,分发与命令表两模共用

✓ 封套只管两件事
① 读一整行:从环形缓冲取字节到 LF → 剥 #seq..*crc → 校 CRC → 查 seq
② 写一整行:resp → #seq status kv *crc → 存幂等单槽
—— 分词、registry 查表、handler 两模完全一样。
✗ 两模唯一的差别
human:读行时回显字符 + 出 agent> 提示,应答不加 seq/CRC。
machine:无回显无提示,每帧 seq+CRC+幂等。
一个全局标志切换,只在帧边界生效,不打断半帧。

A2.2　接缝数据流(一条命令的七步,标注复用/新增)

① UART RX ISR → ringbuff复用 SDK · 只搬字节,最小中断
▼
② 主循环取字节,组行到 LF新增 · 非阻塞 ring_getc
▼
③ unwrap #seq..*crc → 校 CRC → 查 seq新增 · CRC 坏→丢弃不回应;seq 撞→重放
▼
④ parse_kv body → kv_t(cmd + kv[])框架 · 自己按空格分词,无需 shell
▼
⑤ op_find(cmd) 遍历 registry 段框架 · 链接段自注册,无中央表
▼
⑥ handler(kv_t*,resp_t*):kv 读 → cdrv 干活 → resp 填原始量每 IP · 唯一碰 SDK 处
▼
⑦ wrap:resp → #seq status kv *crc → UART TX新增 · 存入单槽缓存(幂等)
接缝只在 ②③⑦ 三点(蓝=新增);① 复用 SDK,④⑤ 是框架一次写好,⑥ 是每 IP 填空。framework 与 IP 的边界正在 ⑤→⑥ 之间。

A2.3　三个易错点,逐一钉死

双模切换
sys mode machine 置全局标志。human 回显 + agent> 提示;machine 无回显、加封套。切换只在帧边界生效,不打断半帧。
LOG 流式 vs 幂等
LOG 行即时发、不进缓存;仅终态行进单槽。重放只重放终态(LOG 是诊断,主机判据只认终态)。
大块 b64 分块
单帧超 FRAME_MAX → 切块。每块 part=i/n + 各自 CRC;主机按 part 拼回。仅大数组走此路,小标量永远一行。

主循环每圈 board_wdg_feed()。某 handler 真死循环 → 停喂 → WDG 复位 → 固件重启 → 主机 RESP_TIMEOUT 超时 → 重发同 seq → 复位后正常应答。坏 IP 不拖垮整机。
为什么不需要 RTOS：协议严格一发一收、无并发命令、无后台任务 → 一个超循环足矣。省掉 RTOS 依赖(osal/task/mutex)→ 更小、更省、更可预测,也不必寄生 et_shell。单在途也是幂等只需单槽缓存的前提。
A5

能力真相流 caps_hash(跨芯片一致性的根)

"加芯片不破坏用例"的可移植性,全靠能力模型。核心问题两个:固件怎么知道自己有哪些能力去上报?两端怎么保证认知一致?

A5.1　唯一真相:生成物做 hash 快断,yaml 做人读核对(并用)

(b) 生成物 caps.def —— 做 fail-fast hash
一份 caps.def(IP 列表 + 路数 + 变体)同时编进固件、被主机加载 → 两端算出的 caps_hash 天然相等。sys ping 一比对,连错板/烧错固件立刻暴露。
(a) capabilities/<chip>.yaml —— 做人读核对
主机侧人类可读的能力表(present / instances / variant)。sys caps 拉固件自描述,与 yaml 逐项核对,驱动四态裁决与用例展开。

A5.2　真相流(编译期 → 上电体检 → 四态裁决)

编译期 caps.def → 固件内建 caps_hash  &&  主机 load(caps.def)→同一 hash
上电 主机 sys mode machine → sys ping → 固件回 caps_hash → 比对:一致放行 / 不符 fail-fast
裁决 主机 sys caps + contract → 每 feature 落一态 → 决定 run / skip / fail

A5.3　四态裁决(全在主机;固件只回 NA 兜底)

present
能力在、已实现 → run
absent
本芯片无此 IP → skip
board / target
板/环境不具备 → skip
not_impl
该有却没实现 → fail
加芯片只动三处:能力表 capabilities/<chip>.yaml + 每 IP 一份 adapter + 一份 board。契约、用例、handler、框架零改动 —— 差异被能力位(有/无)、变体标签(行为变)、适配层(位宽等)三招吸收。

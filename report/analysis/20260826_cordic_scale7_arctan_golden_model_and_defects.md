## 3. 问题清单（逐条陈述）

### 3.1 【严重】期望值 `0x007EBA14` 无法从任何已知文档语义复现

黄金模型（§4）推算 Scale=7 的理论输出为 **`0x007FFFD5`**，而测试期望 `0x007EBA14`。

```text
差值   = 8,388,565 − 8,305,172 = 83,393 LSB
相对差 = 1.0%
```

1% 的偏差**远超任何合理的硬件精度误差**（24bit 引擎底噪 ~1e-7），只能来自期望值的推导错误。附录 A 给出了对 `0x007EBA14` 的逆向分析——尝试了弧度/π单位/有无scale/乘除语义等 8 种组合均无法命中，疑似生成时单位混淆或凭空构造。**且代码中该常量无任何来源注释，违反证据可溯源要求。**

### 3.2 【严重】阈值叙述与代码实现不一致

| 来源 | 阈值表述 | 折算 |
|---|---|---|
| 测试描述文字 | "误差约 1.475e-4，超过 1e-4"（浮点域） | — |
| config.h:117 | `0x216` = 534 LSB | 534 / 2³¹ = **2.49e-7** |

两者相差约 400~600 倍，描述的不是同一把尺子。另外 1.475e-4 这个观测值无法由本代码的判定逻辑（原始整数差 ≤ 534）产生——需要确认实际烧录执行的是否为当前版本源码，或日志是否来自另一次修改过的运行。

### 3.3 【中】单点激励，无覆盖度

整个 case 只投一个输入向量（0.5）。用单个工作点的表现去支撑"Scale=7 精度"的结论，覆盖度不足；且该工作点是全部 8 个档位中**有效输入最小、量化最敏感**的点（手册明文警告小数值输入误差大）。

### 3.4 【中】无解析锚点校验

没有诸如"比值恰为 1 → atan = 45°"这类可手工验证的哨兵用例。一旦单位换算（rad / π单位 / deg）出错，当前测试结构无法自检，只会安静地 FAIL。

### 3.5 【低】实现细节

- `et_manual_cordic_test.c:56-60`：`--wait_count` 先减后判，`WAIT_LIMIT` 用尽时序语义有 off-by-one 嫌疑（影响极小）；
- 轮询仅检查 `CALCULATE_COMPLETE`，未同时监控 bit0（参数溢出）/bit2（ARG2 错误）——若硬件因参数问题异常完成，错误结果会被当作真值参与比对；
- 未读回 CTRL0 确认 SCALE/NOI 位真实生效；
- 失败路径缺少"期望值推导公式"的日志输出，事后排查只能靠猜。

### 3.6 【提示】p2_001 DMA case 的关联风险

`ET_MANUAL_CORDIC_DMA_WORK_MODE = 3`，但 `cordic_cfg.svd` 对 WORK_MODE[11:10]=2'b11 的注释为"DMA搬运模式（**不支持**）"，而 SDK 例程中又存在 CORDIC DMA 示例——两处文档互相矛盾。无论该 case 通过与否，都应把这一矛盾作为芯片事实记录到 `<CHIP>_cordic.md`。

## 4. 黄金模型推导（step by step）

约定：输入 RAW 为 Q31 有符号定点（值 = RAW / 2³¹）；SCALE=n 时引擎有效输入 `x = 输入值 / 2ⁿ`；假设输出 RES1 为**弧度值的 Q31 表示**（该假设的验证方法见 §6）。

### Step 1 有效输入

```text
输入 RAW = 0x40000000 → 值 = 0.5
SCALE = n → x(n) = 0.5 / 2ⁿ
```

### Step 2 计算 arctan（Taylor 展开，收敛极快）

```text
atan(x) = x − x³/3 + x⁵/5 − x⁷/7 + ...
```

以 n=7 为例（x = 2⁻⁸）：

```text
atan(2⁻⁸) = 2⁻⁸ − 2⁻²⁴/3 + 2⁻⁴⁰/5
          = 0.00390625 − 0.0000000198682155 + 0.0000000000000002
          = 0.0039062301317945 rad
```

### Step 3 定点化回 RAW

```text
RAW_out = floor( atan(x) × 2³¹ )
n=7:    floor(0.0039062301317945 × 2147483648)
      = floor(8,388,608 − 42.67)          ← 因为 2³¹ × 2⁻⁸ = 2²³ = 8,388,608
      = 8,388,565
      = 0x007FFFD5                          ★ 黄金期望值
```

### Step 4 与被测常量对比

```text
黄金模型: 0x007FFFD5 (8,388,565)
测试期望: 0x007EBA14 (8,305,172)
差值:     83,393 LSB (1.0%)   → 不是精度问题, 是期望值错误
```

说明：

- 表格可用 §7.3 的 Python 脚本独立复现。

### 5.1 若硬件输出单位为"角度/π"（备选语义）

部分 CORDIC 实现（含 STM32G4）输出以 π 为单位的归一化角度。此时换算公式：

```text
RAW_π = floor( atan(x) / π × 2³¹ )  =  floor( RAW_rad × 0.318309886184 )
```

已双重验算的示例：

| SCALE | RAW_rad | RAW_π (理论) |
|---:|---:|---:|
| 0 | 995,675,660 | 316,933,406 (`0x12E4051E`) |
| 7 | 8,388,565 | ≈2,670,163 |

> 判别方法：拿到一次硬件实测 `actual_raw` 后，分别与两张表的对应行比较，哪个吻合即硬件的真实输出约定。确认后必须写入 `<CHIP>_cordic.md` 固化为芯片事实。

## 6. 观察到的 1.475e-4 的可能来源（待实验定位）

| 假设 | 机理 | 判别实验 |
|---|---|---|
| H1 期望值/单位模型错 | 软件判分标准错，硬件无辜 | 用 §5 表直接对照实测 RAW 即可证实/证伪 |
| H2 小输入量化放大 | 有效输入 ÷128 后尾数有效位减少，量化噪声占比上升（手册警告过） | 固定 SCALE=7 与 NOI，扫描输入幅度 0.5→0.001，看误差是否随幅度减小而增大 |
| H3 迭代次数不足 | arctan 残余误差 ≈ 最末砝码的一半；若实际微旋转只有 8 次，残余 ~10⁻³ 量级 | 固定输入与 SCALE，NOI 从最低扫到最高，看误差是否随之单调下降 |

三个假设不互斥，H1 应最先排除（成本最低）。

## 7. 修复方案

### 7.1 立即动作（不改硬件预期）

1. 将 `ET_MANUAL_CORDIC_ARCTAN_EXPECTED_RAW` 改为黄金模型值 `0x007FFFD5`（或按 §5.1 判别结果改为对应 π 单位值）；
2. 重跑 case：
   - PASS 且 delta 在个位数 LSB → 结案：原期望常量错误，芯片无缺陷；
   - 仍 FAIL → 进入 §6 H2/H3 扫描实验，并用实测数据反推硬件输出约定。

### 7.2 测试结构增强

```text
① 激励矩阵化: 每个 Scale 取其推荐范围内 {low, mid, high} 三点
              + 解析锚点 (输入比=1 → atan=45°)
② 双参考: PC端 double 独立计算 + 手工解析锚点
③ 日志增补: 期望推导公式字符串、CTRL0 读回值、原始RES hex
④ 标志位检查: 轮询循环同时监测 STATUS_RPT 的 bit0/bit2
⑤ 阈值来源化: 按 §5 表建立 per-Scale 精度预算数组,
              并同步记录到 test_case_doc/<chip>/cordic 文档
```

### 7.3 黄金值复现脚本（附录）

```python
import math

INPUT_RAW = 0x40000000
Q31 = 1 << 31

def q31(v: float) -> int:
    return math.floor(v * Q31)

print(f"{'SCALE':>5} {'x':>12} {'atan(x) rad':>18} {'RAW_dec':>12} {'RAW_hex':>12}")
for n in range(8):
    x = (INPUT_RAW / Q31) / (2 ** n)
    r = math.atan(x)
    print(f"{n:>5} {x:12.9f} {r:18.15f} {q31(r):12d} {hex(q31(r)):>12}")
```

在本机 Python 3（math.atan 为 double 精度）下运行应逐行复现 §5 表格。

### 7.4 容差建议

- 模型校准阶段：容差 16~64 LSB（覆盖截断/舍入及末次迭代残余）；
- 量产门限：待表征数据（多板、多温）到位后按 P99 设定，写入精度预算文档；
- 当前 534 LSB 的容差本身不算离谱，问题不在容差大小，而在**期望值中心不对**。

## 8. 经验教训

1. **AI 生成的期望值必须附带可复现的推导**——本次 `0x007EBA14` 无出处、无公式、无法复现，是整个失败的根源；
2. **"稳定复现的失败"优先怀疑判分标准而非被测物**：确定性误差更可能来自确定性的模型错误；
3. **涉及单位换算的测试必须有解析锚点**，否则单位错误不可见；
4. 描述文档与代码中的阈值必须同源同值（R110）。

## 附录 A：对错误常量 `0x007EBA14` 的逆向分析

`0x007EBA14` = 8,305,172 → Q31 值 = 0.00386689。

| 尝试语义 | 推算结果 | 是否命中 |
|---|---|---|
| atan(0.5/128) rad-Q31 | 0x007FFFD5 | ✗ |
| atan(0.5/128) π单位-Q31 | ≈0x0028Bxxx | ✗ |
| atan(0.5) rad-Q31 再 ÷128 | 0x0076B4DC | ✗ |
| atan(0.5) π单位-Q31 再 ÷128 | ≈0x0018Bxxx | ✗ |
| scale 解释为 ×2ⁿ: atan(64)（超Q31上限） | 不可能 | ✗ |
| atan(0.5) deg 混入 rad 计算 | 各组合均不匹配 | ✗ |

结论：无法复现。0.00386689 与真值 0.00390623 相比恰好偏低约 1%，不排除生成时使用了错误的泰勒项、单精度中间量或干脆为构造值。建议向生成会话索要该常量的推导过程；无法提供则一律废弃。

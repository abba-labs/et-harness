# CAN_P1_011 · irq_lines_and_clear

**原函数**：`test_can_p1.py::test_can_p1_011_irq_lines_and_clear`。

**固定行为对照**：[B的源文件](https://github.com/abba-labs/et-harness/blob/d6b91b65fd96c04f80e87e954c463be48607288b/pc/et_test_platform/test_cases/can/test_can_p1.py)。本卡为实施规定，不是执行结果。

## 1. 测试目的

验证屏蔽下Raw、保留pending后真实双线路ISR、选择性W1C及再次触发。

## 2. 已指定的拆分决定

先修原ID。之后可拆irq_mask_pending_routes与irq_selective_clear_retrigger；原ID归后者。两个子目均保留三mode×两tx_line并自己重建Raw/第一次ISR。

## 3. 具体优化位置

- 原配置/帧向量外移；line1纯计算明确保留：TX_COMPLETE if tx_line else RX_FIFO0_NEW。

## 4. 必须保持的硬件步骤

1. reset配置；两个源为RX_FIFO0_NEW|TX_COMPLETE，另一源在另一条线。
2. 关闭投递，真实收发，检查两Raw且ISR=0。
3. 使用irq_capture_pending保留Raw并绑定/开放；等待实际ISR，检查双线归属。
4. 逐源W1C，证明另一个源不被清；Ack/停止，再产生原第二笔数据并重新验证。
5. internal无盒子；external/normal保留B实际Peer收发、无echo和设备错误；按mode决定是否回发。

## 5. 不可丢失的判据

- **A1**：irq_mask_set的False是enabled=False，不能误认为解除屏蔽。
- **A2**：两线路精确Source/配置读回、实例/事件/次数/故障字段。
- **A3**：两Raw、ISR零基线、选择性清除、第二笔完整帧与新中断、原窗口和对端证据。

原完整函数中的其他断言和参数也需在逐项Ledger中有去向；本卡摘要不是删掉未列字段的许可。

## 6. 本卡明确禁止

- 漏capture；用Start清掉已存在pending；两源都路由tx_line。
- 为了收到帧不分mode额外补发，改变FIFO数量。

## 7. 必须执行的错误反例

- 缺绑定、pending被清、线路互换/两源同线、清错源、第二笔不再投递，必须失败。

反例优先在软件测试边界注入；不是授权对真实设备增加未批准的破坏性刺激。必须记录预期失败位置/类型，不把任意NameError、未连设备或Fixture失败当Feature检测成功。

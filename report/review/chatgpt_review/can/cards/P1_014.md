# CAN_P1_014 · timeout_sources

**原函数**：`test_can_p1_timeout.py::test_can_p1_014_timeout_sources`。

**固定行为对照**：[B的源文件](https://github.com/abba-labs/et-harness/blob/d6b91b65fd96c04f80e87e954c463be48607288b/pc/et_test_platform/test_cases/can/test_can_p1_timeout.py)。本卡为实施规定，不是执行结果。

## 1. 测试目的

验证四计数源自然Timeout、重装和禁用暂停。

## 2. 已指定的拆分决定

本轮不拆baseline→enabled→disabled；FIFO非空时的禁用对照必须保留。四source参数不变。

## 3. 具体优化位置

- timing/RAM/bus与source到FIFO/filter的选择为纯数据；阶段动作直接可读。

## 4. 必须保持的硬件步骤

1. reset；TOP1000/分频1/500k和三FIFO空基线。
2. 启用：连续源reload，FIFO源只使选定队列非空。
3. 等待自然Raw与真实ISR，读取到期计数，消费/Ack并验证重装。
4. 禁用且FIFO源再次保持非空；至少两倍period持续无IRQ/计数不下降。

## 5. 不可丢失的判据

- **A1**：配置读回、非目标两FIFO为空、Fill/Lost。
- **A2**：连续源和FIFO源不同计数上界、精确ISR/诊断。
- **A3**：reload前后真实值、禁用窗口逐次计数、原帧与Event type。

原完整函数中的其他断言和参数也需在逐项Ledger中有去向；本卡摘要不是删掉未列字段的许可。

## 6. 本卡明确禁止

- Force代替自然到期；空FIFO冒充有效禁用对照；reset替代连续策略变化。

## 7. 必须执行的错误反例

- RX1选择却刺激RX0、禁用无效、Raw有但ISR无、窗口不足、消费后不重装，必须失败。

反例优先在软件测试边界注入；不是授权对真实设备增加未批准的破坏性刺激。必须记录预期失败位置/类型，不把任意NameError、未连设备或Fixture失败当Feature检测成功。

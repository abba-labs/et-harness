# CAN_P1_020 · fd_format_matrix

**原函数**：`test_can_p1_format.py::test_can_p1_020_fd_format_matrix`。

**固定行为对照**：[B的源文件](https://github.com/abba-labs/et-harness/blob/d6b91b65fd96c04f80e87e954c463be48607288b/pc/et_test_platform/test_cases/can/test_can_p1_format.py)。本卡为实施规定，不是执行结果。

## 1. 测试目的

验证ISO/Non-ISO匹配、真实失配错误及ISO恢复。

## 2. 已指定的拆分决定

允许拆fd_format_matched_exchange_recovery与fd_format_mismatch_recovery；四组合×16/64字节逐行映射，原ID归失配链。两个子目均保留B的ISO恢复。

## 3. 具体优化位置

- 500k/2M/BRS配置、原自动重发/协议异常选项、帧输入外移为纯数据。

## 4. 必须保持的硬件步骤

1. reset/原两端配置并独立读回。
2. 失配Peer单发→真实错误Raw→首次consume协议状态→从刺激起补足100ms零RX。
3. 保存现场、原清错误/复位与ISO重建→双向完整收发。
4. 匹配节点按B双向传输后也执行ISO恢复。

## 5. 不可丢失的判据

- **A1**：实际格式和重发读回；失配必须IRQ+有效首个LEC/DLEC+零RX。
- **A2**：NONE/UNCHANGED不作有效错误；恢复帧、无echo/Fill/Lost/BusOff/清IRQ终态。

原完整函数中的其他断言和参数也需在逐项Ledger中有去向；本卡摘要不是删掉未列字段的许可。

## 6. 本卡明确禁止

- 只用超时证明格式拒绝；先发成功帧洗掉首次错误；干净启动替代故障恢复。

## 7. 必须执行的错误反例

- 首错被消费、只有超时无协议错误、失配有效入队、恢复只单向、窗口不足，必须失败。

反例优先在软件测试边界注入；不是授权对真实设备增加未批准的破坏性刺激。必须记录预期失败位置/类型，不把任意NameError、未连设备或Fixture失败当Feature检测成功。

# CAN_P1_018 · tsu_capture

**原函数**：`test_can_p1_tsu.py::test_can_p1_018_tsu_capture`。

**固定行为对照**：[B的源文件](https://github.com/abba-labs/et-harness/blob/d6b91b65fd96c04f80e87e954c463be48607288b/pc/et_test_platform/test_cases/can/test_can_p1_tsu.py)。本卡为实施规定，不是执行结果。

## 1. 测试目的

验证TSU时间基、New/Lost、TS0读清及分频参考。

## 2. 已指定的拆分决定

允许拆tsu_capture_new_lost_readclear与tsu_internal_divider_ratio；原ID归捕获。比率子目自己重建TSU与STIMER，不依赖前一用例。

## 3. 具体优化位置

- TSU/event_format/layout配置数据外移；STIMER真实取样动作保留。

## 4. 必须保持的硬件步骤

1. 保留internal、两个原固定向量、真实STIMER样本四timebase，以及实际支持的EOF/SOF。
2. 按真实槽数N，最多N次TX定位TS0 New，读TS0确认仅清本槽。
3. 再2N次TX不读槽形成Lost，读取并再次核对局部读清。
4. 比率子目以真实STIMER前后包围比较4/16分频。

## 5. 不可丢失的判据

- **A1**：向量、ATB、TS0分别真实读取，外部逐bit正确；STIMER是样本而非假定硬连线。
- **A2**：内部小于半量程包围；非目标槽保留；全部TX完成。
- **A3**：归一化TSU/STIMER速率区间相交和原25%不确定度。

原完整函数中的其他断言和参数也需在逐项Ledger中有去向；本卡摘要不是删掉未列字段的许可。

## 6. 本卡明确禁止

- 不断consume TS0导致Lost永不形成；假timestamp；只保留外部读回。

## 7. 必须执行的错误反例

- 向量回显但ATB不变、清全部槽、无Lost、divider无效、timer静止，必须失败。

反例优先在软件测试边界注入；不是授权对真实设备增加未批准的破坏性刺激。必须记录预期失败位置/类型，不把任意NameError、未连设备或Fixture失败当Feature检测成功。

# CAN_P1_010 · message_marker_width

**原函数**：`test_can_p1_marker.py::test_can_p1_010_message_marker_width`。

**固定行为对照**：[B的源文件](https://github.com/abba-labs/et-harness/blob/d6b91b65fd96c04f80e87e954c463be48607288b/pc/et_test_platform/test_cases/can/test_can_p1_marker.py)。本卡为实施规定，不是执行结果。

## 1. 测试目的

验证8/16-bit Marker完整传递、两项事件保留及格式有效性。

## 2. 已指定的拆分决定

本轮不拆；已有marker_bits参数化，两事件与尾窗保留。

## 3. 具体优化位置

- 8-bit 0x12/0xAB、16-bit 0x1234/0xABCD及A/B输入外移。

## 4. 必须保持的硬件步骤

1. reset/原配置，真实格式读回。
2. 两笔TX/RX逐帧核对，Event暂不Ack，使两项同时保留。
3. 读取两项事件、全部字段比较并Ack。
4. 连续100ms观察RX/Event无额外项。

## 5. 不可丢失的判据

- **A1**：格式、完整RX、TX/Pending/Cancelled、逐笔Event Fill/Lost。
- **A2**：完整Marker、事件全部原字段；原DAR的type=2。
- **A3**：宽格式timestamp=None、TSU pointer=None；窄格式timestamp有效范围；完整尾窗。

原完整函数中的其他断言和参数也需在逐项Ledger中有去向；本卡摘要不是删掉未列字段的许可。

## 6. 本卡明确禁止

- 只比低8位；将宽Marker位当timestamp；尾窗一次读。

## 7. 必须执行的错误反例

- 高字节丢失、第二项覆盖第一项、假timestamp、窗口中途多余帧均须失败。

反例优先在软件测试边界注入；不是授权对真实设备增加未批准的破坏性刺激。必须记录预期失败位置/类型，不把任意NameError、未连设备或Fixture失败当Feature检测成功。

Event两项同时保留有实际状态；记录不能在第二次读时覆盖第一次。

## 后续工作方式

按实际基线建立逐 Case 行为/接口/断言对照，分批实现、自检、实际验证、上传精确提交后复核。开发任务遵循现有 Task Context 与范围检查；针对已批准设计的规则冲突做准确最小同步，不关闭整个检查体系。

报告备注只展示 FAIL 的失败项，PASS 留空；原始状态、日志、Observation 和错误原因继续保留。CAN 优化与公共报告改动分开提交。
